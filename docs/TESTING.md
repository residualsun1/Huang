# 网站测试与内容维护

这份说明用于解释项目为什么需要自动测试，以及怎样避免测试妨碍正常写作。

## 三类文件各自负责什么

- `content/`：正式网站内容。文章可以新增、修改、改名或删除。
- `tests/fixtures/`：固定测试样本。它们不会发布，只用于验证 Markdown 功能。
- `tests/site.test.mjs`：测试规则。它验证结构和链接，不应要求某篇正式文章永久存在。

可以把它们理解为：

> 正式文章是书架上的书；测试夹具是实验室里的标准样品。

如果用书架上的某一本书作为标准样品，删除这本书就会让实验失败。把标准样品单独保存后，书架便可以正常整理。

## 删除文章时会发生什么

构建器会重新读取 `content/`，生成新的归档页以及上一篇、下一篇链接。测试会动态检查：

1. 当前文章能否完成构建；
2. 归档页中的链接是否都有对应页面；
3. 翻页链接是否只指向仍然存在的文章；
4. 输出中是否残留无法识别的旧 Hugo 短代码。

测试不会再把某个正式文章标题或 slug 当作永久条件。

## 修改渲染功能时怎么做

如果修改 notice、表格、脚注、代码块等 Markdown 功能：

1. 在 `tests/fixtures/markdown/legacy-features.md` 中保留一个最小示例；
2. 在 `tests/site.test.mjs` 中检查该示例的输出结构；
3. 运行 `npm test`；
4. 确认所有测试通过后再提交。

这样即使正式文章以后被删除，渲染功能仍有稳定的回归测试。

## 推送前自动检查

在每个本地克隆中运行一次：

```powershell
npm run hooks:install
```

安装后的 `pre-push` hook 会在每次 `git push` 前执行 `npm test`。检查失败时推送会停止，修复后重新推送即可。GitHub Actions 仍会在远端重新执行相同检查，避免本地环境差异绕过验证。

## 换行符的分工

- `.editorconfig` 提醒编辑器以 LF 保存文本；
- `.gitattributes` 保证 Git 仓库最终以 LF 存储文本；
- `.bat` 和 `.cmd` 文件仍使用 CRLF。

不要全局启用自动删除行末空格。Markdown 的两个行末空格可能表示显式换行。
